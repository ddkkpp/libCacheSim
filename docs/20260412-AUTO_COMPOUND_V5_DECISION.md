# Auto-Compound v5 决策文档

> **变更日期**: 2026-04-12
> **变更文件**: `libCacheSim/cache/eviction/LOH.c` auto_compound 决策块
> **数据来源**: `tmp/20260411-feature-ablation/` (1111 traces × 8 configs)

## 1. 概述

将 auto_compound 从 v4 升级为 v5，核心变更：**freq/rec (FR) 从固定关闭改为固定开启**。

| 项目 | v4（旧） | v5（新） |
|------|---------|---------|
| **FR (freq/rec)** | 固定关闭 `= 0` | **固定开启 `= 1`** |
| FS (freq/size) | r1 > 0.98 → 关 | 不变 |
| RS (rec×size) | r2 > 0.98 → 关 | 不变 |
| 默认配置 | f011 | **f111** |

## 2. 变更理由

### 2.1 v4 关闭 FR 的原始依据（已推翻）

v4 关闭 FR 基于两个论据：

1. **理论**：`log1p(freq/rec) ≈ log(freq) - log(rec)`，可被基础权重 w0(freq) 和 w1(rec) 线性近似 → 信息冗余 + 维度诅咒
2. **实证**：109 trace 消融，关 FR 的 avgLoss=0.002 < 开 FR 的 avgLoss=0.006

### 2.2 v4 依据的三个缺陷

| # | 缺陷 | 说明 |
|---|------|------|
| 1 | **仅看 MR，忽略 BMR** | v4 的 avgLoss 是 MR gap to MR-oracle。FR 对 MR 确实微有害（+0.12%），但对 BMR **大幅有益**（-2%~-25%）。v4 从未评估 BMR |
| 2 | **样本量不足** | v4 使用 109 traces；v5 基于 1111 traces（10× 数据量） |
| 3 | **搜索空间不完整** | v4 的 autocompound 分析只比较 f0XX（f000/f001/f010/f011），从未与 f1XX 对比 |

## 3. 数据支撑

### 3.1 实验设计

- **Feature 配置**: f[FR][FS][RS]，8 种组合（f000~f111）
  - FR = freq/rec (weights[3])
  - FS = freq/size (weights[4])
  - RS = rec×size (weights[5])
- **Traces**: 1115 traces，其中 1111 有完整 8 config 结果 + WARMUP_DIAG
- **评估指标**: Joint = 0.5 × MR + 0.5 × BMR
- **分组**: cloudphysics (106), alibaba (998), metaCDN (3), metaKV (5), wiki (3)

### 3.2 FR 的边际效应（Joint 指标，vs f0XX → f1XX）

FR 对每组的平均 Joint 改善：

| 组 | FR 边际效应 (Mean) | 方向 |
|----|-------------------|------|
| cloudphysics | **-4.12%** | 有益 |
| alibaba | **-0.94%** | 有益 |
| metaCDN | **-0.40%** | 有益 |
| metaKV | **-9.27%** | 有益 |
| wiki | **-7.76%** | 有益 |

**FR 在全部 5 组均有益**，且对 metaKV 和 wiki 改善最显著。

### 3.3 FR 拆解：MR vs BMR

| 组 | FR 对 MR | FR 对 BMR |
|----|---------|----------|
| cloudphysics | +0.35% (微损) | **-4.12%** (有益) |
| alibaba | +0.12% (微损) | **-2.01%** (有益) |
| metaCDN | +0.21% (微损) | **-1.02%** (有益) |
| metaKV | -0.12% (微益) | **-18.42%** (有益) |
| wiki | +2.32% (微损) | **-17.84%** (有益) |

**结论**：FR 对 MR 的微损（+0.1~2%）远小于对 BMR 的大幅改善（-2~-18%）。v4 仅看 MR 而得出"FR 冗余"的结论是片面的。

### 3.4 策略模拟比较

使用真实 WARMUP_DIAG 数据模拟不同策略的 per-group 平均 Joint：

| 策略 | cloudphysics | alibaba | metaCDN | metaKV | wiki | TOTAL |
|------|-------------|---------|---------|--------|------|-------|
| v4 (FR=0, r1/r2=0.98) | 0.4851 | 0.4054 | 0.2578 | 0.0730 | 0.1387 | 0.2720 |
| **v5a (FR=1, r1/r2=0.98)** | **0.4793** | **0.4040** | **0.2568** | **0.0675** | **0.1279** | **0.2671** |
| Oracle (per-trace 最优) | 0.4689 | 0.3950 | 0.2563 | 0.0638 | 0.1221 | 0.2612 |

**v5a vs v4 改善**：

| 组 | 改善 |
|----|------|
| cloudphysics | -1.2% |
| alibaba | -0.3% |
| metaCDN | -0.4% |
| metaKV | -7.5% |
| wiki | -7.8% |
| **TOTAL** | **-1.8%** |

### 3.5 oracle 覆盖率

v4 captures oracle improvement: (0.2720 - 0.2720) / (0.2720 - 0.2612) = 0%（v4 是基准）
v5a captures oracle improvement: (0.2720 - 0.2671) / (0.2720 - 0.2612) = **45.4%**

## 4. r1/r2 阈值分析

### 4.1 r1 阈值（FS 门控）

r1 = Pearson(freq, freq/size)。r1 高表示 size 均匀 → freq/size 与 freq 冗余 → 关闭 FS。

r1 阈值扫描（FR=1 固定，RS gated by r2>0.98）：

| r1 阈值 | cloudphysics | alibaba | wiki | TOTAL |
|---------|-------------|---------|------|-------|
| 0.95 | 0.4808 | 0.4038 | 0.1317 | 0.2678 |
| 0.96 | 0.4796 | 0.4043 | 0.1297 | 0.2672 |
| 0.975 | 0.4796 | 0.4042 | 0.1279 | 0.2672 |
| **0.98** | **0.4793** | **0.4040** | 0.1279 | **0.2671 ★** |
| 0.99 | 0.4833 ↑ | 0.4103 ↑ | 0.1279 | 0.2691 |
| 0.995 | 0.5051 ↑↑ | 0.4179 ↑ | 0.1267 | 0.2748 |

**r1=0.98 是全局最优**。提高到 0.99+ 会释放 cloudphysics 中 7 个极端异常 trace（w33/w36/w39/w40/w41/w45/w47），它们 r1 在 0.989~0.993，FS 开启后 Joint 劣化 137%~453%。

这 7 个 trace 的特点：object size 近乎均匀（r1≈0.99），freq/size 几乎等价于 freq，额外维度引入噪声导致 CMA-ES 搜索失效。

### 4.2 r2 阈值（RS 门控）

r2 = Pearson(rec, rec×size)。r2 阈值**极不敏感**：

| r2 阈值 | TOTAL |
|---------|-------|
| 0.50 | 0.26707 |
| 0.90 | **0.26706** |
| 0.98 | 0.26710 |
| 1.0 (RS 全开) | 0.26707 |

全范围变化仅 0.004%。原因：r2>0.98 的 trace 全局仅 8 个，且 RS 关/开对它们影响微小（最大 -0.99%）。

**结论**：r2=0.98 保持不变，或取消门控（RS 始终开启）均可，差异可忽略。

## 5. wiki_2019t 特殊案例

wiki_2019t 的 r1=0.9915 > 0.98，触发 FS 关。但 FS 对 wiki_2019t 实际有益（oracle 是 f110）。

| 策略 | 配置 | Joint |
|------|------|-------|
| v4 | f001 | 0.1669 (最差) |
| v5a | f101 | 0.1559 |
| Oracle | f110 | 0.1512 |

虽然 v5a 未选到 oracle (f110)，但相比 v4 改善 6.6%，且无法通过提高 r1 阈值解决（会释放 cloudphysics 地雷）。wiki_2019t 是少数"r1 高但 FS 仍有益"的 trace，属于可接受的次优。

## 6. 实施代码

LOH.c 第 ~7220 行，auto_compound 决策块：

```c
// v4:
loh_use_freq_rec = 0;  // 固定关闭

// v5 (已实施):
loh_use_freq_rec = 1;  // 固定开启（BMR 改善远超 MR 微损）
```

FS/RS 门控逻辑（r1>0.98→关 FS, r2>0.98→关 RS）保持不变。

## 7. 限制与未来方向

1. **Joint 权重固定为 0.5/0.5**：如果用户更侧重 MR 或 BMR，最优配置可能不同
2. **wiki_2019t 次优**：r1 gate 无法精确区分"size 均匀但 FS 仍有益"的 trace
3. **r2 gate 近似无效**：考虑在未来版本中移除 r2 门控，简化为 RS 始终开启
4. **数据覆盖**：当前分析基于 5 组 1111 traces；新 trace 类型可能需要重新验证
