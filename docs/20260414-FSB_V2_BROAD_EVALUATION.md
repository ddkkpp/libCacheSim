# FSB v2 广域测试评估报告

**日期**: 2026-04-14
**实验目录**: `tmp/20260415-fsb-v2-broad/`
**结论**: FSB v2 **有一定价值，但尚不够可靠**。中位 MR regret 仅 2.78%（多数情况可接受），但有 ~17% 的 trace 出现 ≥20% 的严重 regret。

---

## 1. 实验设计

- **FSB v2 参数**: block_size=n_obj/4, max_rounds=5, min_rounds=2, warmup_rounds=0, ucb_c=1.0
- **8 arms**: f000~f111，编码为 f{freq_rec}{freq_size}{rec_size}
- **环境**: LOH_FSB=1, LOH_ENABLE_CMAES=1, LOH_ENABLE_RL=0, LOH_AUTO_COMPOUND=0, LOH_FEATURE_LOG1P=1
- **Oracle 基准**: 从 feature ablation（每个 trace 跑全部 8 种 config）的 `.cachesim` 结果文件中提取 MR/BMR 最优 config
- **测试范围**: 8 组 46 条 trace，实际有效 43 条（alibaba_45/287 缺文件，w64 FSB 未锁定 → NO_LOCK）
- tencent_photo1 FSB 已锁定 f100，CMA-ES 阶段仍在运行（不影响 FSB 评估）

## 6. 评估结论

### 6.1 FSB v2 的优势
1. **多数情况可接受**: 60% 的 trace regret <5%，84% <20%
2. **零成本自动化**: 免去手动 ablation 的 8× 运行开销
3. **某些组非常准**: wiki (median +0.1%)、metaCDN (+2.5%)、cloudphysics (median +2.8%)

### 6.2 FSB v2 的问题
1. **Oracle 命中率偏低**: 仅 30% 精确命中 MR 最优 config
2. **尾部风险显著**: 16% 的 trace MR regret ≥20%，最极端 +533%
3. **5 轮不够区分**: 某些 config 间 MR 差异微小（如 f010 vs f011 仅差 0.2%），5 轮 UCB 的噪声掩盖了真实差异
4. **对 BMR 的选择更差**: BMR 命中率仅 19%

### 6.3 FSB v2 vs AUTO_COMPOUND v5 对比 (n=43)

AUTO_COMPOUND v5 的逻辑：FR(freq×rec) 固定开启，FS(freq×size) 由 r1>0.98 决定，RS(rec×size) 由 r2>0.98 决定。其选择空间限定在 f1xx 子集（f100/f101/f110/f111），而 FSB 的搜索范围覆盖全部 8 种 config。

r1/r2 值来源：feature ablation 日志中的 `WARMUP_DIAG` 打印。

|------|--------|-------|
| MR regret 平均 | **+22.38%** | +38.17% |
| MR regret 中位 | **+2.78%** | +7.89% |
| MR regret p90 | **+31.43%** | +88.81% |
| FSB 胜出 | **32/43 (74.4%)** | 10/43 (23.3%) |

**结论**: FSB v2 在所有维度上显著优于 AC v5 (FR=ON):

- 每个 trace 组 FSB 都胜出或持平

AC v5 (FR=ON) 的核心劣势：搜索空间仅限于 f1xx（FR 固定开启），当 oracle 最优 config 是 f0xx（如 f000, f001, f010, f011）时完全无法到达。FSB 没有这个限制。

#### 6.4.4 分析

- **AC FR=OFF 整体比 FR=ON 略好**（median 7.16% vs 7.89%），但两者互有胜负（21:21 平局）。
- **FR=OFF 在 tencentBlock 和 twitter 组优势明显**：这两组 oracle 最优 config 大多在 f0xx 子集。
- **FR=ON 在 wiki 和 alibabaBlock 组略优**：wiki 数据 oracle 多为 f1xx；alibaba 虽 oracle 多 f0xx，但 FR=ON 对 r1/r2 gating 的误差更小。
- **FSB v2 仍全面领先**：对 AC_OFF 胜率 65.1%，中位 regret 2.78% vs 7.16%。FSB 在 5/7 组的 avg 和 median 均最优。
- **AC_OFF 能在局部胜 FSB**：tencentBlock(5/10) 和 twitter(2/3) 中 AC_OFF > FSB，因为这些 trace 的 f0xx oracle config 恰好在 AC_OFF 的搜索空间内，且 r1/r2 gating 准确。

**总结**: 固定 FR=OFF 后 AC v5 有一定改善，但不如固定 FR=ON 改善明显。两种 FR 固定策略各有适用场景，没有一致优势。FSB v2 不预设 FR 的开闭，因此更灵活、更稳健。

### 6.6 改进方向
- **增加 min_rounds**: 从 2 提高到 3-4，减少因噪声导致的过早锁定
- **使用加权 regret（绝对值而非百分比）**: 低 MR 基线的 trace 百分比 regret 放大不具参考性
- **组级先验**: 对已知特性的组（如 alibabaBlock 以 f000/f001 为主）设置先验分布
- **Multi-metric 目标**: 同时考虑 MR + BMR 做 arm 选择，避免 MR/BMR 最优配置分裂

### 6.7 最终判断

> **FSB v2 作为"免调参的默认策略"是有用的** — 多数情况下 regret 可控（median ~3%），优于盲猜。
> 但它**不能替代 full ablation** 用于要求最优结果的场景（命中率仅 30%，尾部 regret 可达 +97%）。
> 建议定位为"快速筛选"工具：先用 FSB 跑一遍获得基线，对 regret 敏感的场景再做 targeted ablation。
