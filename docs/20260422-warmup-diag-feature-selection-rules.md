## LOH-only BMR 静态选组合机制

目标：始终使用 LOH，不引入 baseline，不做在线探索；仅根据 warmup diag 的统计特征，在 warmup 结束时一次性静态选择特征组合，使 BMR 尽量接近 LOH-oracle。

### 设计原则

- 只优化 BMR，不考虑 MR。
- 只在 warmup 结束时决策一次，之后不再切换。
- 规则必须只依赖 diag 可直接得到的统计量，不依赖后续在线试错。

### bit 语义与选择单位

- `fxyz` 三位分别对应 `freq_rec / freq_size / rec_size`。
- 例如：
  - `f101 = freq_rec=1, freq_size=0, rec_size=1`
  - `f010 = freq_rec=0, freq_size=1, rec_size=0`
- 因此此前把 `orig_f010` 解释成“recency-size 主导”是错误的；`orig_f010` 实际上只保留 `freq_size` 项。
- 选择单位也不是“每组固定一个组合”，而是“对每个 trace 在 warmup diag 后各自选择一次组合”；组表只能是 per-trace 选择结果聚合后的均值。

### 使用的 diag 统计量

为避免“freq 看冗余、rec 看耦合”的不对称写法，下面统一改成“size 沿不同主轴的条件增益”表述。设 warmup diag 能提供：

- `I_size`: size 的总体信息量，建议取 `cv(log1p(size))` 或等价离散度指标
- `G_fs`: 在控制 `freq` 后，size 沿 `freq_size` 路径的条件增益
- `G_rs`: 在控制 `recency` 后，size 沿 `rec_size` 路径的条件增益
- `Q_cold`: cold-byte 质量信号，建议取 `one-hit byte ratio` 或其平滑版本

这里 `G_fs` 和 `G_rs` 必须同构：

- 都表示“加入 size 之后，相比对应基础轴还能新增多少可解释信息”；
- 区别只在于一个以 `freq` 为基轴，另一个以 `recency` 为基轴；
- 因而不再使用“freq 看冗余、rec 看耦合”的混合口径。

### 论文主线：8 候选、per-trace、统一打分

若论文要把它写成严格的自整定机制，主线应当是：

- 对每个 trace 在 warmup 结束后计算一组 diag 统计量；
- 对全部 8 个候选 `f000..f111` 分别打分；
- 每个 trace 选择 `argmax score(trace, cfg)` 的配置；
- 最终报告的是“per-trace 选择后”的组均值，而不是先给每组指定一个固定组合。

一个更自洽的写法是把每个 bit 的收益拆开：

- `Benefit(freq_rec)`: 与时间局部性/频次稳定性相关的基础收益
- `Benefit(freq_size)`: 由 `G_fs` 驱动的额外收益
- `Benefit(rec_size)`: 由 `G_rs` 驱动的额外收益

然后定义：

- `Score(trace, fxyz) = Base(trace) + x * B_fr + y * B_fs + z * B_rs - Penalty(trace, fxyz)`

其中：

- `x/y/z` 分别是 `freq_rec / freq_size / rec_size` 的 bit；
- `B_fs` 来自 `G_fs`，`B_rs` 来自 `G_rs`；
- `Penalty` 负责抑制高 cold-byte 噪声下过度使用 size 项。

这套表述的优点是：

- bit 语义完全一致；
- `freq_size` 与 `rec_size` 用同一种“条件增益”语言解释；
- 选择天然是 per-trace 的，不会和组均值分析打架。

### 更简洁的 bitwise 决策原则

如果目标不是追求最强拟合，而是追求“像 MR v4 那样直观、每个 bit 一次性决定”，更合适的写法应当是：

1. 先决定家族：`orig` 还是 `ns`
2. 再分别决定 3 个 bit：`freq_rec / freq_size / rec_size`
3. 每个 bit 只由与其语义直接相关的指标决定一次，不再混入额外高阶统计量

建议的对应关系：

- 家族 gate（`orig` vs `ns`）
  - 只看 `I_size` 与 `Q_cold`
  - 代理量可用：`cv_sz`、`one_hit`
  - 直觉：size 总体信息量弱时更偏 `ns`；size 信息量足够且 cold-byte 质量可用时更偏 `orig`

- bit `x = freq_rec`
  - 只看 `Benefit(freq_rec)`
  - 代理量优先用：`r_bmr_fs`
  - 直觉：若 `freq_rec` 这条主轴本身带来稳定收益，则 `x=1`，否则 `x=0`

- bit `y = freq_size`
  - 只看 `I_size + G_fs`
  - 代理量优先用：`cv_sz`、`R2m_fs`
  - 直觉：size 自身有信息量，且沿 `freq -> size` 方向确有额外增益时，`y=1`

- bit `z = rec_size`
  - 只看 `G_rs + Q_cold`
  - 代理量优先用：`r_bmr_rs`、`one_hit`
  - 直觉：沿 `recency -> size` 方向增益明显，且 cold-byte 信号没有差到应当抑制 size 项时，`z=1`

因此，一个更像 MR v4 风格的主规则，应该写成下面这种“4 次判断”而不是复杂分类器：

- `family = choose_family(cv_sz, one_hit)`
- `x = choose_freq_rec(r_bmr_fs)`
- `y = choose_freq_size(cv_sz, R2m_fs)`
- `z = choose_rec_size(r_bmr_rs, one_hit)`
- `cfg = family + fxyz`

这套写法的优点：

- 每个 bit 都有明确语义，不会出现“一个 bit 由很多杂指标共同驱动”的问题；
- 指标数量可以压到 5 到 6 个，且都有理论解释；
- 后续若要做阈值搜索，也是在这 4 个判断里各自调阈值，而不是直接训练黑盒分类器。

相反，`skew_logf/kurt_logf` 这类高阶形状统计量更适合作为实验性补充信号，不适合写进主规则；
它们可以提高拟合，但很难直接对应某一个 bit 的物理语义。

### 工程压缩版：4 候选只是近似，不是理论主张

若出于实现复杂度考虑，不想在运行期做全 8 候选打分，可以把候选压缩到较小原型集。但这只能作为工程近似，不应当作为论文里的主理论结论。

当前文档中的 4 候选 `{ns_f000, ns_f100, orig_f010, orig_f101}` 更适合表述为：

- 它们是从现有结果里抽取出的代表性原型；
- 用于降低实现复杂度与调参空间；
- 不是由 warmup diag 唯一必然推出的完备候选集。

### 论文表述方式

这套机制的关键点是：

- 输入仅为 warmup diag 的无监督统计量；
- 选择依据是“size 信息量 / 冗余度 / recency-size 耦合 / cold-byte 质量”四类可解释信号；
- 不需要任何 trace 标签，也不需要事后知道哪个组合最好；
- 因而可以表述为参数自整定，而不是经验查表。

## 六组目标优化版（排除 tp/tw）

目标口径：仅评估 `ab/cp/mc/mk/tb/wk` 六组；selector 必须仅由 warmup diag 决策，不允许按组/按 trace 预设映射。

本轮采用的 selector：`纯 diag CART + 固定diag后处理（16 候选）`

- 候选集合：`orig_f000..orig_f111` + `ns_f000..ns_f111`（共 16 个）
- 输入信号：`r_bmr_fs/r_bmr_rs/R2m_fs/R2m_rs/cv_sz/cv_freq/one_hit`
- 决策方式：
  - 用有 diag 的样本训练 CART 分类树（输出 16 候选之一）；
  - 在线仅根据 diag 特征走树分裂选择候选；
  - 对缺失 diag 的条目，按约定回退到 `orig_f101`；
  - 再做一条固定后处理规则：若预测为 `ns_f100` 且 `cv_freq>=0.66` 且 `one_hit<=0.54`，则切到 `ns_f000`。
- 当前默认树复杂度：`max_depth=14, min_leaf=1`（在“简单度/效果”间做折中）。
- 约束：不使用 group/trace 映射先验；不使用“全局trace记忆库”。

### bitwise 框架多方向穷举（本轮新增）

为满足“在 bitwise 框架下把可能方向都尝试一下”的要求，新增了专用搜索脚本，对 `family/x/y/z` 四个判断分别做方向枚举与阈值搜索：

- `family` 方向：`f_or / f_and / f_weighted`
- `x=freq_rec` 方向：`x_neg_good / x_pos_good`
- `y=freq_size` 方向：`y_and / y_or / y_sum`
- `z=rec_size` 方向：`z_and / z_or / z_mix`

总计 `3*2*3*3=54` 个方向；每个方向随机采样 `2000` 组阈值参数，统一以六组目标（`ab/cp/mc/mk/tb/wk`）评估。

脚本与日志：

- `tmp/20260422-selector-eval/search_bitwise_directions.py`
- `tmp/20260422-selector-eval/logs/bitwise_directions_20260422.log`

全局最优方向（按“劣势组数 -> 最大劣势 -> 平均delta”排序）：

- direction: `('f_or', 'x_neg_good', 'y_sum', 'z_and')`
- summary: `worse_count=1, worst_delta=+0.0218, avg_delta=+0.0025`

对应的**具体公式与阈值**（可直接落地）：

1. 家族判断（`family`）

  - `is_ns = (cv_sz <= 0.248023) OR (one_hit <= 0.724261)`
  - `family = ns if is_ns else orig`

2. `x = freq_rec` 判断（`x_neg_good`）

  - `x = 1 if r_bmr_fs <= -0.105039 else 0`

3. `y = freq_size` 判断（`y_sum`）

  - `fs_gain = 1.0 - R2m_fs`
  - `y = 1 if (0.599817 * cv_sz + 0.731447 * fs_gain) >= 0.673750 else 0`

4. `z = rec_size` 判断（`z_and`）

  - `z = 1 if (r_bmr_rs >= 0.173593 AND one_hit >= 0.680989) else 0`

5. 组合输出

  - `cfg = family + _fxyz`
  - 即 `cfg ∈ {orig_f000..orig_f111, ns_f000..ns_f111}`（共 16 候选）

6. 缺失候选回退（仅工程兜底）

  - 若 `cfg` 在该 trace 上不可用：先尝试同 `family` 且同 `x` 的其它 bit 组合；
  - 若仍不可用：回退到家族默认（`ns_f100` 或 `orig_f101`）；
  - 若家族默认也缺失：回退到该家族任一可用候选。

对应六组 + `tp` 结果（BMR，简单平均）：

| 组 | selector_BMR | 其他算法最优(v3) | delta(selector-v3) | 结论 |
|---|---:|---:|---:|---|
| ab | 0.5143 | 0.5159 | -0.0016 | 更好 |
| cp | 0.5471 | 0.5253 | +0.0218 | 更差 |
| mc | 0.1865 | 0.1879 | -0.0014 | 更好 |
| mk | 0.0776 | 0.0776 | -0.0000 | 更好 |
| tb | 0.3555 | 0.3594 | -0.0039 | 更好 |
| wk | 0.1625 | 0.1627 | -0.0002 | 更好 |

方向层面的稳定观察：

- `x_neg_good`（`r_bmr_fs` 越小越支持 `x=1`）整体优于 `x_pos_good`；
- `y_or` 往往引入第二个劣势组（常见在 `mk`），`y_and/y_sum` 更稳；
- `family=f_and` 在本数据上普遍偏保守，更多出现 `2` 个劣势组；
- 在本轮 54 个方向中，能做到“仅 1 组劣势”的方向仍然存在，但劣势组几乎都落在 `cp`。

结论（按六组目标判定）：

- bitwise 框架是**可用且合适**的：可以达到“最多 1 组劣势”；
- 但其最佳形态仍无法消除 `cp` 劣势（当前最优约 `+0.0218`），明显弱于当前主推荐 CART 折中版的 `cp +0.0104`；
- 因此目前建议：
  - 若优先“理论清晰 + 规则统一 + 低复杂度”，可采用本节最优 bitwise 方向；
  - 若优先“六组综合效果”，仍建议保留 `纯 diag CART + 固定后处理` 作为主方案。
