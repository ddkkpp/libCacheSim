# FS (freq/size) Compound Feature 影响分析

**日期**: 2026-04-20
**数据来源**: `docs/20260415-ablation-per-group/cmaes版本LOH/` 下 8 组 ablation 文档
**分析脚本**: 交互式 Python 分析（见 Copilot 对话记录）
**目的**: 评估 v5 autocompound 中 FS compound (freq×size) 的启用/禁用对 MR 和 BMR 的影响

## 1. 背景

v5 autocompound 策略使用 `r1 = r(freq, freq/size)` 的阈值 0.98 决定是否保留 FS compound：
- `r1 < 0.98` → 启用 FS (f111 = freq + rec + size + freq/size + rec×size + freq/rec)
- `r1 ≥ 0.98` → 禁用 FS (f101 = freq + rec + size + rec×size + freq/rec，无 freq/size)

核心问题：这个决策是否正确？FS compound 是否对所有 r1<0.98 的 trace 都有帮助？

## 6. 核心矛盾

FS compound 的 **MR vs BMR 效果矛盾**：
- **cloudphysics/metaCDN/wiki**: FS 有帮助（尤其 wiki BMR +0.012）
- **twitter/tencentBlock/metaKV**: FS 有害（尤其 twitter BMR −0.019，tencentBlock BMR −0.006）

单一全局阈值无法同时满足两端需求。

## 7. 结论与建议

### 7.1 FS compound 的实际价值

- 在 r1<0.98 的 2688 条 trace 上，FS **总体弊大于利**
- MR 维度仅带来 +0.001 的微弱改善，BMR 维度反而造成 −0.005 的损害
- FS 唯一明确有帮助的组是 wiki（BMR +0.012）和 cloudphysics（MR +0.010）

### 7.2 阈值调整建议

| 方案 | 改动 | MR 效果 | BMR 效果 | 推荐场景 |
|---|---|---|---|---|
| **保守: T=0.95** | 最小改动 | −0.0005 | −0.0004 | 低风险优化 |
| **推荐: T=0.85** | 全局 MR/BMR 最优 | −0.0005 | −0.0013 | 通用最优 |
| **激进: always_f101** | 完全弃用 FS guard | −0.0001 | −0.0011 | 简化代码 |
| **per-group 策略** | 每组独立选 perfeat | 更大改善 | 更大改善 | 长期优化方向 |

### 7.3 更大的优化杠杆

**阈值调整的 BMR 改善量级仅约 0.001**，远小于 per-group perfeat 选择带来的 0.01~0.05 级别差异。真正的优化方向是：
- wiki → f110（BMR 最优）
- metaKV → f100（BMR 最优）
- twitter → f100/f101（BMR 最优）
- tencentBlock/alibabaBlock → f101（BMR 微弱最优）
- cloudphysics → 保持 f111（MR 最优）或 f100（BMR 最优）

这属于 v6b / per-group 策略的范畴，不是单一 r1 阈值能解决的。
