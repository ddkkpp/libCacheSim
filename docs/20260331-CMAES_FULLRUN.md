# 20260331 CMA-ES Full Run Report (Updated)

## 1. 代码逻辑校正（按当前实现）

### 1.1 CMA-ES 入口与互斥关系

- `LOH_ENABLE_CMAES=1` 时，C 侧会强制关闭 RL 同步（`loh_enable_rl = 0`）。
- 也就是说：同一个 case 下，CMA-ES 与 RL 不是并行叠加，而是互斥模式。

关键代码位置：
- `libCacheSim/cache/eviction/LOH.c`

### 1.2 按函数说明当前代码做了什么

`LOH.c` 侧（调度与集成）：

1. 初始化阶段（`LOH_init`）
- 读取 `LOH_ENABLE_CMAES / LOH_CMAES_LAMBDA / LOH_CMAES_INIT_MEAN / LOH_CMAES_INIT_SIGMA / LOH_CMAES_ALGO / LOH_CMAES_FEEDBACK`。
- 创建 CMA-ES 句柄后，进入 C 侧窗口化 ask/tell 流程。
- 当开启 CMA-ES 时，关闭 RL 同步路径，避免双写权重。

2. 同步阶段（`sync_with_cmaes`）
- 每个窗口结束后，先以窗口 miss ratio 或 byte miss ratio（可选，见下）执行一次 `tell`。
- 然后立即 `ask` 下一组候选并写回 `params->weights`。
- 如果 ask/tell 次序异常导致 ask 失败，会补做一次 tell（同样用当前反馈指标）再 ask。
- 若候选出现非有限值，优先回退到上一轮有效权重，再回退到中性值，最后写入当前权重。

**反馈指标选择说明：**
- 通过环境变量 `LOH_CMAES_FEEDBACK=miss`（默认）或 `byte` 控制。
- miss：对象未命中率（miss ratio）；byte：字节未命中率（byte miss ratio）。
- 所有 ask/tell 路径（包括极端 fallback）均严格使用该指标。
- 日志输出 `[CMAES] gen=... feedback=... (miss/byte) next_w=[...]` 明确标注。

3. 对外可观测行为
- 通过 `[CMAES] gen=... feedback=...(miss/byte) next_w=[...]` 输出每轮代数与权重。

`loh_cmaes_bridge.cpp` 侧（优化器桥接）：

4. 对外 C ABI 函数（C 侧只调用这些）
- `loh_cmaes_create(dim, lambda, init_mean, init_sigma)`：构造 `OnlineCMAES` 对象并返回句柄；失败返回 `nullptr`。
- `loh_cmaes_destroy(handle)`：释放优化器句柄。
- `loh_cmaes_ask(handle, out_w, out_dim)`：请求一个候选；成功返回 1，失败返回 0。
- `loh_cmaes_tell(handle, fitness)`：提交当前候选的 fitness；返回最新 generation。
- `loh_cmaes_get_generation(handle)`：读取当前 generation。
- `loh_cmaes_get_last_best_fitness(handle)`：读取最近一代 best fitness（当前 `LOH.c` 主调用链未使用）。
- `loh_cmaes_reset_sigma(handle, sigma)`：重置步长（当前 `LOH.c` 主调用链未使用）。

5. libcmaes 分支（`#ifdef LOH_USE_LIBCMAES`）内部函数级逻辑
- `parse_algo_id(raw_algo)`：把 `LOH_CMAES_ALGO` 文本映射到算法 id（default/ipop/bipop/active/sep/vd 及其组合）。
- `is_sep_algo / is_vd_algo / is_active_algo`：按算法 id 分类，决定优化器类型和参数标志。
- `OnlineCMAES::OnlineCMAES(...)`：
  - 规范化入参（维度、lambda、初始均值、初始 sigma）。
  - 构造 `GenoPheno<pwqBoundStrategy>`，并注入 `CMAParameters`。
  - 调 `set_algo`、按需 `set_sep`/`set_vd`。
  - 调 `build_optimizer()` 建立优化器，再 `refill_population()` 拉取第一代样本。
- `build_optimizer()`：按算法家族选择 `Vanilla`/`Active`/`VD` 优化器封装。
- `refill_population()`：
  - 调 `optimizer_->ask()` 生成内部空间候选（genotype）。
  - 通过 `gp_.pheno(...)` 生成输出空间候选（phenotype，映射到 [0,1]）。
  - 先在 genotype 侧修复非有限值（NaN/Inf -> 0.5），再做 `gp_.pheno(...)`。
  - phenotype 侧仅做非有限值兜底，不做手工 bound/clip。
  - 当 `LOH_CMAES_TRACE_RANGE=1` 时输出 `[CMAES RANGE]` 审计日志（raw_min/raw_max/nonfinite/below/above）。
  - 重置代内状态：`fitness_`、`next_idx_`、`pending_idx_`。
- `ask(out_w)`：
  - 从 phenotype 候选中取第 `next_idx_` 个候选。
  - 记录 `pending_idx_` 防止 tell 对错样本。
  - 将候选拷贝到 `out_w`（多余维度补 0）。
- `tell(fit)`：
  - 把 fitness 写回 `pending_idx_`。
  - 若本代未收齐，只推进索引；若收齐则：
    - 把内部空间候选（genotype）与 fitness 回填到 `solutions()`。
    - 依次执行 `optimizer_->tell()` 与 `optimizer_->inc_iter()`。
    - 更新 `generation_` 与 `last_best_`。
    - 调 `refill_population()` 开启下一代。
- `reset_sigma(sigma)`：
  - 使用当前 best 解（若可取）作为新起点。
  - 重建 `CMAParameters` 与优化器，再重新采样一代。

6. fallback 分支状态
- 当前代码已移除 Eigen fallback 分支，编译期要求 `LOH_USE_LIBCMAES=ON`。
- 目的：统一使用 libcmaes 的 ask/tell 与边界策略，避免双实现路径行为分叉。

7. 端到端调用链（运行时）
- `LOH.c::sync_with_cmaes()`
  -> `loh_cmaes_tell()`
  -> （桥接层代内/代间更新）
  -> `loh_cmaes_ask()`
  -> 写回 `params->weights`
  -> 下一窗口继续。

### 1.3 算法名与内部逻辑

当前支持（`LOH_CMAES_ALGO`）：

1. `cmaes` / `default`
- 标准 CMA-ES（全协方差）。

2. `ipop`
- IPOP-CMA-ES，重启时增大种群规模。

3. `bipop`
- BIPOP-CMA-ES，两类重启预算交替（大/小种群）。

4. `acmaes`
- Active CMA-ES，使用负权重协方差更新抑制坏方向。

5. `aipop`
- Active + IPOP。

6. `abipop`
- Active + BIPOP。

7. `sep`
- sep-CMA-ES，对角协方差，复杂度更低。

8. `sepipop`
- sep + IPOP。

9. `sepbipop`
- sep + BIPOP。

10. `sepacmaes`
- sep + Active。

11. `sepaipop`
- sep + Active + IPOP。

12. `sepabipop`
- sep + Active + BIPOP。

13. `vd`
- VD-CMA（低秩/向量化协方差近似）。

14. `vdipop`
- VD + IPOP。

15. `vdbipop`
- VD + BIPOP。

### 6.2 同 trace 同算法下，mr/bmr 反馈是否各自在对应指标占优

核对口径：对每个 `trace + algo`，比较两条记录：
- `feedback=miss` 是否满足 `miss_ratio(miss) < miss_ratio(byte)`。
- `feedback=byte` 是否满足 `byte_miss_ratio(byte) < byte_miss_ratio(miss)`。

全量统计（45 对）：
- `mr` 在 miss 上占优：22 对。
- `bmr` 在 byte 上占优：26 对。
- 两者同时成立：12 对。
- 两者都不成立：8 对。

分 trace 统计：
- 1063：`mr`占优 5/15，`bmr`占优 11/15。
- meta：`mr`占优 10/15，`bmr`占优 6/15。
- wiki：`mr`占优 8/15，`bmr`占优 9/15。

结论：
- 不是所有同算法对都满足“mr 在 miss 上胜过 bmr、且 bmr 在 byte 上胜过 mr”。
- 两种反馈对不同算法/trace 存在明显交互，不是单调主导关系。
