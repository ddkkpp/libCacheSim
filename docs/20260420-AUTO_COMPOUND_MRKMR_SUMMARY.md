# AUTO_COMPOUND 策略 MR/BMR 汇总对比

基于 `docs/20260415-ablation-per-group/` 中 5883 条 trace 的消融数据，对 6 个 AUTO_COMPOUND 策略进行 MR（Miss Ratio）和 BMR（Byte Miss Ratio）的全面对比分析。

**关键概念**：
- **oracle(best_cfg)** = 对每条 trace 独立选取其最优配置（f000~f111），然后求均值
  - `oracle_MR` 和 `oracle_BMR` 分别独立计算（每条 trace 对 MR 和 BMR 的最优配置可能不同）
  - 代表理论上界，无法在线达到（因为运行时无法完美预知配置）

**策略定义**:
- `v4(FR=0,r1r2)`: FR=0 固定，FS=(r1≤0.98)?1:0，RS=(r2≤0.98)?1:0
- `v5(FR=1,r1r2)`: FR=1 固定（当前实现），FS=(r1≤0.98)?1:0，RS=(r2≤0.98)?1:0
- `v6(FR=cv,RS=1)`: FR=(cv_freq<0.55)?1:0，FS=(r1≤0.98)?1:0，RS=1
- `v6b(FR=cv,RS=r2)`: FR=(cv_freq<0.55)?1:0，FS=(r1≤0.98)?1:0，RS=(r2≤0.98)?1:0
- `always_f111`: 始终选择 f111 配置（频率+大小+时间均开启）
- `always_f011`: 始终选择 f011 配置（仅频率不开启）

### 结论与建议

**为什么 v5(FR=1) 是当前实现？**

v5 在 v4 选出后被作为改进版本，核心原因是：
- **MR vs BMR 权衡**：虽然 v5 的 MR 比 v4 差 +2.1%，但 BMR 优势显著（-2.7%）
- **regret 指标**：v5 的平均 regret 仅 6.59%，远低于 v4 的 15.39%，说明 v5 的决策更稳定可靠
- **极端情况保护**：v4 最大 regret 达 3064.50%；v5 仅 1221.51%，风险更小

**MR 与 BMR 的权衡**：
- MR 反映**对象数量**的缓存效率
- BMR 反映**字节大小**的缓存效率
- 在请求量加权后，v5 的综合表现仍优于 v4（加权 regret 平衡两个维度）

**何时切换回 v4？**

如果业务场景：
1. **只关心对象命中率**（不关心字节节省），推荐 v4
2. **同时优化对象数+字节**（更常见的生产场景），应保持 v5
3. **需要极致稳定性**（允许 MR 稍差），v6/v6b 是安全折中

**其他策略不推荐**：
- `always_f111` / `always_f011`：完全忽略 trace 特性，性能均差
